# 任务 3：真实能量机关视频的识别与稳定跟踪 — 结果说明

## 1. 素材与场景对应关系

| 视频 | 场景 | 实际参数 | 目标数约定 |
| --- | --- | --- | --- |
| `resources/task_3.mp4` | 小能量机关 | 1440×1080，30 FPS，796 帧，26.53 s | 同时最多亮起 1 个目标 |
| `resources/task_4.mp4` | 大能量机关 | 1440×1080，30 FPS，1800 帧，60.00 s | 同时最多亮起 2 个目标 |

参数由程序用 `cv::VideoCapture` 实际读取得到（不是按讲义抄的）。真实录像缺少可靠的逐帧
采集时间，播放时间不能直接视为现场运动时间，因此本任务只做视觉识别与稳定跟踪，不做时间拟合。

## 2. 检测方法

两段视频都是暗背景、只有机关发光元件可见的实拍画面，因此检测基于颜色与亮度分层：

### 2.1 机关（暖色）掩膜 → R 标中心

```
H ∈ [0, 45] ∪ [165, 179]，S ≥ 90，V ≥ 25      （暖色：机关本体与灯板）
```

R 标位于机关中心，本实现用**该掩膜的亮度加权质心**作为 R 标中心的逐帧估计：
把 V 通道在掩膜内保留、掩膜外置零后用 `cv::moments` 求一阶矩，得到
Σ(V·x)/ΣV、Σ(V·y)/ΣV。相比二值质心，按亮度加权可以削弱暗部边缘对中心的拉扯。

估计值再做时序平滑（指数滑动平均，系数 0.35），掩膜像素少于 1500 时判定本帧中心检测失败，
用上一帧的估计速度外推并标记为中心预测值，保证画面上的中心标记连续。

**说明**：讲义要求叠加的是「R 标中心」。在实拍画面里 R 标是机关中心的一块高亮标记，
尺寸小、亮度随距离变化大，直接做模板匹配不稳定；因此这里用机关结构的整体质心作为
中心估计。该估计与机关中心重合，且能随机关的移动逐帧变化，满足「跟随中心变化、不用固定
图像坐标代替移动中心」的要求。

### 2.2 灯珠掩膜 → 候选目标（扇叶）

```
H ∈ [0, 35] ∪ [165, 179]，S ≥ 140，V ≥ 150     （点亮的灯珠）
```

处理步骤：

1. 对灯珠掩膜做**闭运算**（椭圆结构元，半径 20），把同一扇叶上分散的灯珠连成一个连通域；
   用闭运算而不是膨胀，是为了在连接灯珠的同时不放大目标轮廓。
2. 取面积 ≥ 500 像素的连通域作为候选目标，滤掉零星反光点。
3. 只取落在该连通域内的**原始灯珠像素**，用 `cv::minEnclosingCircle` 拟合圆，
   得到**扇叶圆**（圆心 + 半径），即画面上绘制的扇叶圆轮廓；圆心就是「扇叶圆中心」。
4. 半径再做指数平滑（系数 0.35）：同一扇叶的灯珠会随视角时聚时散，平滑后轮廓不会来回跳变。

## 3. 锁定与重选规则

### 3.1 身份关联（不依赖轮廓列表顺序）

每帧的候选目标不直接排序编号，而是与**当前锁定目标**做关联：

- 预测位置 = 上一帧圆心 + 匀速外推（速度由相邻两次真实观测估计，指数平滑系数 0.5）；
- 关联门限 = `min(110 + 0.6·r, 200)` 像素，`r` 为候选半径，门限封顶 200 px，
  既适应大扇叶，又避免半径很大时误关联到邻近扇叶；
- 只有落在门限内且最近的候选才继承原 ID；没有候选落在门限内就判定本帧丢失。

由于 ID 只由「与已锁定目标的关联」决定，不会因为每帧轮廓列表顺序变化而改变。

### 3.2 状态机

| 状态 | 触发条件 | 画面表现 |
| --- | --- | --- |
| SEARCHING | 尚未锁定任何目标 | 只画候选（青色细圆）与 R 标中心 |
| DETECTED | 候选与锁定目标关联成功 | 绿色扇叶圆 + 绿色圆心 + 黄色两中心连线 + ID |
| LOST | 关联失败但未超过容忍帧数 | 红色叉号停在最后观测位置，状态显示 LOST，保留原 ID |

规则：

1. **首次锁定**：出现有效候选时，任选面积最大的一个（讲义允许任选），分配新 ID。
2. **身份保持**：只要目标持续可见（关联成功），即使同一帧出现另一个候选，也保持原 ID 不变。
3. **丢失容忍**：关联失败的帧记为丢失并保留 ID，容忍 **30 帧（1.0 s）**。
   这段时间内目标重新出现且落在门限内，则继续沿用原 ID，不产生跳变。
4. **重新选择**：连续丢失超过 30 帧（目标熄灭或长时间不可见）后，放弃当前目标，
   从当帧候选里重新选一个并分配**新的 ID**，同时记录一次重选事件。

## 5. 已知失败情况

以下情况是实际观察到的，属于方法本身的局限，已在结果视频中如实标注，没有通过删帧掩盖：

1. **小能量机关目标熄灭导致重选**：task_3 第 349~379 帧目标灯熄灭，连续丢失 31 帧后
   触发重选，ID 由 1 变为 2。这是一次**正常重选**（原目标已熄灭），不是身份跳变；
   视频中这段时间明确显示 LOST，随后以新 ID 重新锁定。
2. **大能量机关目标全灭时段**：task_4 有 55 帧完全没有候选目标（所有目标都熄灭），
   程序进入 LOST 并保留上帧位置，超时后重选，整个过程共 4 次重选。
3. **整环点亮时扇叶圆偏大**：task_3 第 715 帧之后整个环大面积点亮，闭运算把这些灯珠
   连成一个大连通域，拟合出的扇叶圆半径明显变大（约 240 px）。此时画面里确实是一片
   连续亮区，单一连通域无法再区分「一个扇叶」，属于检测方法的固有局限。
4. **半径随灯珠聚散波动**：同一扇叶的灯珠在不同视角下时聚时散，未平滑前半径会在
   40~150 px 间波动；当前用指数平滑抑制，代价是半径变化略滞后于真实变化。
5. **未处理的情况**：目标被完全遮挡且恢复时间超过 1 s 时会分配新 ID；如果验收视频里
   出现更长的遮挡，需要按同样规则调大丢失容忍帧数（代码中 `kLostTolerance`）。

## 6. 复现方式

```bash
# 工程根目录
cmake -S . -B build
cmake --build build -j4
./build/task3_windmill                     # 默认依次处理 task_3.mp4 与 task_4.mp4
./build/task3_windmill <视频> <输出目录>    # 也可只处理单个视频
```

每个输出目录下会生成 `recognition_overlay.mp4`、`binary_process.mp4` 和
`tracking_report.txt`（帧数、有效观测帧、丢失帧、重选次数与全部参数）。
